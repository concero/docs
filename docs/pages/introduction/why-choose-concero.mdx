# Why Choose Concero?

Concero gives developers control over cross-chain message delivery and verification, without forcing one global trust model.

## 1) Security as a configurable stack

![Concero's Security Model for Message Verification](/images/concero-v2-message-verification.png)

For each message, you choose:

- one relayer module (`relayerLib`),
- one or more verifier modules (`validatorLibs` in current interface naming),
- destination-side verification policy in your app contract.

This keeps security explicit and application-specific.

## 2) Fast integration path

![Concero's Integration Process](/images/concero-v2-time-cost.png)

You can ship a minimal integration with:

1. `ConceroClient` receiver on destination,
2. `MessageRequest` builder on source,
3. API-based tracking for operations.

Start at [Getting Started](/integrate-concero/getting-started).

## 3) Modular architecture

![Concero's Universal Connectivity](/images/concero-v2-unlimited-chains.png)

Relayer and verifier modules are pluggable. Apps are not tied to a single protocol-wide trust assumption.

## What this means for integrators

- You can keep strict verification assertions for high-value flows.
- You can define lighter policies for low-risk flows.
- You can evolve module choices over time without rewriting app business logic.

:::note
Current Concero-run relayer/verifier modules are admin-gated via allowlists/roles. Apps can choose custom modules, including permissionless implementations.
:::
