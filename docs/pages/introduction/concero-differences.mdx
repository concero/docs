# What Makes Concero Different

Concero V2 focuses on **cryptographic message security** with a **configurable verification stack**.

Instead of enforcing one global trust model, each message can define which relayer module and verifier modules are used. The destination app contract then authenticates and asserts the message using its own policy.

![Concero's Message Security](/images/concero-v2-dual-layer-security.png)

## Cryptographic Verification by Default

Concero verification is based on cryptographic artifacts and destination-chain checks. In practice, this includes:

- Signature recovery to confirm node authenticity
- Quorum-based verifier assertions (defined by selected modules and app policy)
- Hash verification to ensure data integrity during transmission

## Stack-Defined Security

Security depends on which modules are selected in the message stack:

- **Relayer module (`relayerLib`)**: pricing and submitter authorization.
- **Verifier modules (`validatorLibs` in the current interface naming)**: cryptographic verification checks.
- **Destination app policy**: final authentication/assertion logic in `ConceroClientBase` / `ConceroClient`.

:::note
Current Concero-run relayer and verifier modules are configured with allowlists/roles. Developers can choose other custom modules, including permissionless implementations, in their own message stacks.
:::
