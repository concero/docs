# Receiving a Message

Concero lets your contract react to messages sent from other blockchains by overriding the internal `_conceroReceive` hook defined in `ConceroClient`. Whenever a cross-chain message arrives, the router calls this function so you can implement custom processing logic.

## Function Signature

```solidity
function _conceroReceive(
    bytes32 messageId,
    uint24 srcChainSelector,
    bytes calldata sender,
    bytes calldata message
) internal override
```

## Parameters

| Parameter          | Type      | Description                                                                                |
| ------------------ | --------- | ------------------------------------------------------------------------------------------ |
| `messageId`        | `bytes32` | Unique identifier for the incoming message, generated by the Concero router                |
| `srcChainSelector` | `uint24`  | Identifier of the source chain from which this message was sent                            |
| `sender`           | `bytes`   | Raw bytes representing the sender’s address on the source chain (e.g., packed EVM address) |
| `message`          | `bytes`   | Payload of the incoming message                                                            |

## Usage Example

```solidity
import {ConceroClient} from "./ConceroClient.sol";

contract MessageReceiver is ConceroClient {
    /// @notice Emitted when a message is received via Concero
    event MessageReceived(
        bytes32 indexed messageId,
        uint24 indexed srcChainSelector,
        address indexed sender,
        bytes data
    );

    mapping(address => bool) isAllowedSender;
    mapping(uint24 => bool) isAllowedChainSelector;

    constructor(address conceroRouter) ConceroClient(conceroRouter) {}

    function _conceroReceive(
        bytes32 messageId,
        uint24 srcChainSelector,
        bytes calldata sender,
        bytes calldata message
    ) internal override {
        // 1. Decode the sender bytes into an address (for EVM chains)
        address senderAddress = abi.decode(sender, (address));

        require(isAllowedSender[senderAddress], "invalid sender");
        require(isAllowedChainSelector[srcChainSelector], "invalid src chain selector");

        // 2. Insert your custom processing logic here
        //    e.g. _processMessage(messageId, srcChainSelector, senderAddress, message);

        // 3. Emit an event so off-chain services can index the arrival
        emit MessageReceived(messageId, srcChainSelector, senderAddress, message);
    }
}
```

## Important Notes

* **Inherit ConceroClient and supply the correct router address.** Always extend from ConceroClient and pass in the real ConceroRouter instance to its constructor. This guarantees that only your designated router can invoke conceroReceive.
* **Decoding `sender`**: The `sender` field is raw bytes; decode it according to the source chain’s address format (e.g., `abi.decode(sender, (address))` for EVM).
* **Gas Considerations**: All processing happens within the cross-chain execution context—ensure you allocate enough gas on the source side if your logic is complex.
* **Always validate the decoded sender.**
Decode the raw sender bytes into an address (e.g. abi.decode(sender, (address))) and check it against your whitelist of trusted senders.
* **Always validate the srcChainSelector.**
Confirm that srcChainSelector matches one of the expected chain IDs you support before processing the message.
