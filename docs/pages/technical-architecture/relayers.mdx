# Concero V2 Relayers

In **Concero V2**, relayers are **opt-in and per-message**.

There is **no protocol-level global relayer registry**. A relayer is selected per message through `messageRequest.relayerLib`.

In practice, usability depends on the selected `relayerLib` policy:

1. users **explicitly select** that `relayerLib`,
2. and the `relayerLib` may enforce submitter authorization (for example, allowlists in Concero-run modules).

If a user doesn’t point to your relayer module, you won’t be responsible for that message.

> **Current status:** at the moment there is one Concero-run relayer in production: `concero`.


## Key idea: relayer = chosen `relayerLib`

Concero’s router treats the relayer as a **contract address** (`messageRequest.relayerLib`) that defines two things:

* **Pricing**: how much native fee is required to deliver a message (`IRelayerLib.getFee`)
* **Authorization**: who is allowed to submit messages on behalf of that relayer (`IRelayerLib.validate`)

So the network doesn’t maintain a “relayer set”. **Users pick the relayer by picking the relayer’s `relayerLib` address.**

:::note
The current relayer is run by Concero, and uses its allowlisted submitters. Apps can choose other custom relayer networks, including permissionless implementations.
:::


## Relayer responsibilities (V2)

If users select your relayer (`relayerLib`) you’re expected to:

1. **Monitor `ConceroMessageSent`** for your `relayerLib`
2. **Build a destination submission**:

* gather verifier proofs (`validations`) corresponding to the message’s verifiers
* call `submitMessage(...)` on the destination router
3. **Maintain uptime + gas** on destination chains (and any infra needed to source proofs)
4. **Handle failed deliveries**:

* resubmit if appropriate,
* or use retry flow when a submission is marked retryable

## Notes for integrators

* The router does **not** enforce “at least N verifiers must pass” at the protocol level; it forwards `validationChecks` (verification checks) to the receiver. Your receiver contract decides what must be asserted.
* If a selected relayer module has only one authorized submitter and it is down, delivery may halt. If the module authorizes multiple submitters, failover is possible.
