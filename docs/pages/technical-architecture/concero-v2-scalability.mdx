# Concero V2 Scalability

Concero V2 is designed so adding routes and chains does not require every app to rebuild its cross-chain stack from scratch.

## Main scaling idea

Separate concerns:

- **Apps** choose relayer/verifier modules per message.
- **Modules** handle delivery and verification logic.
- **Ops pipeline** handles network onboarding and module configuration.

This keeps app integration surface area small.

## What scales well

- One consistent send/receive contract interface.
- Per-message module selection instead of fixed global route assumptions.
- Deterministic message receipts for indexing and retries.

## Cost model summary

Message fee is dynamic and depends on:

- selected relayer module,
- selected verifier modules,
- chain fee inputs used by those modules.

There is no fixed universal fee schedule.

## Security model at scale

Concero V2 uses cryptographic verification with stack-defined security.

Security level depends on:

1. selected relayer module,
2. selected verifier modules,
3. destination app assertion policy.

## Integrator guidance

- Start with strict destination assertions and known module set.
- Add routes incrementally.
- Use tracking and retries as part of standard operations.

:::note
Current Concero-run relayer/verifier modules are admin-gated via allowlists/roles. Apps can use custom modules, including permissionless implementations.
:::

:::note
Custom RPC selection via relayer/verifier metadata is planned but not available yet.
:::
